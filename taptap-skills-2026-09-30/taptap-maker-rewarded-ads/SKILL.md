# TapTap Maker 激励广告接入与优化

用于实现或诊断 Maker Lua 游戏的激励广告。先追踪实际 SDK、请求入口、回调、奖励和前后台事件；说明与诊断请求不授权修改或发布。

## 接入前
- 确认目标项目目录与绑定。读取该项目 AGENTS.md、Maker 的 maker://ads-integration-guide（可用时）、get_ad_config 和本地 SDK 文档。以当前工具声明与广告配置为准；缺失时报告限制，不借用其他 TapTap 平台接口。
- SDK 未启用、无填充、网络错误、加载超时、播放器取消、奖励回调缺失分别处理。
- 不复制来源游戏的广告 ID、项目 ID、云键或测试开关。预览成功不能证明手机广告可用。

## 请求与奖励
- 各入口共用广告服务。请求保存唯一序号、来源、发起页面/局次、尝试编号、奖励快照、完成标记；阻止重复点击和并行播放。
- SDK 回调只入队，回到游戏更新循环再处理 UI 与奖励，避免直接在外部回调中重建渲染对象。
- 区分“释放加载按钮”和“终结奖励请求”：超时可以恢复按钮，但迟到的可信成功回调仍需按原请求补发一次。旧回调不能清掉新请求的按钮状态。
- 仅平台确认成功后发奖；取消、失败、测试绕过不计真实观看。奖励成功与奖励落账是不同状态，错误不能用“已保留”掩盖；按项目持久化能力设计补偿。
- 发奖读取原局次/商品快照，不能读取已切换页面的新结算对象。完成后保存，并用 toast 显示实际得到的现金、道具等。
- 一次请求内重复回调、重复成功、旧尝试回调均须去重。进程退出后的恰好一次需要持久化凭证或服务端支持，内存布尔值不足。

## 加载、重试与恢复
- 只在当前 SDK 明确支持预加载时接入 preload；绝不以播放广告模拟预热。记录点击、调用、展示、回调耗时，定位平台等待与游戏自身等待。
- 对明确的加载失败做有限重试；示例是最多追加1次、有短间隔、页面仍有效且未开始展示。取消、不明播放状态或进入后台后不盲目重播。
- 加载超时与广告播放时长分开；前后台切换时暂停加载判断，返回后留回调宽限。时间参数由实测决定。
- 广告返回时清理暂态输入，按引擎文档恢复渲染与音频。音频同时检查设备、BGM源、SFX源、设置音量与静音状态；使用短时有限恢复窗口，避免每帧重建或强开用户静音。
- iPhone 失声需多轮实机广告、锁屏、后台返回验证。Lua 没报错或单次重启音频不是已修复证据。

## 验证与交付
验证成功、取消、失败后一次重试、加载超时、迟到成功、重复回调、页面切换、广告中切后台及关闭音乐。分别报告本地、Maker构建、手机验证；只有明确要求构建才执行目标项目 Maker 工作流。
